# 診断実行ルール（実行前に必ず読む）

このファイルは、診断本番を進める間ずっと参照する運用ルールをまとめたもの。
質問文そのものは `questions.md`、配点の設計根拠は `scoring.md`・`types.md`、
提案導線は `funnel-design.md` を参照する（これらは診断設計・改善の作業時のみ読む）。

## 進め方の原則

- 質問は必ず1問ずつ出す。`第n問／全m問`、場面、4選択肢（標準版はA〜D）を示す。
- 診断中は配点・測定意図・途中結果を見せない。説明を求められたら終了後に開示する。
- 回答がどれにも合わなければ自由回答を受け、最も近い選択肢を本人に確認してから
  A〜Dのいずれかとして記録する。この「最も近い」への読み替えが1診断中に5問以上
  発生したら、結果を「確信度：低」として明示する。
- タイプ・現在課題・事業段階・提案は別々に判定する。タイプから現在課題を推定しない。
- タイプは人格や能力の優劣ではなく、今回の会社・局面での意思決定傾向として扱う。
  「能力100点」ではなく「今回の回答傾向」と表記し、心理検査・医学的診断・
  科学的に実証済みの分類とは表現しない。

## タイプ判定（標準版25問）

配点表の正本は `data/scoring.json`（`points.primary=3`／`points.secondary=1`）。
固定値をこのファイルや会話中に書き写さない。

1. 各問の回答から、選択肢に対応する主要タイプへ+3、副次タイプへ+1を加点する。
2. 全問後、各タイプの生点を理論最大点（そのタイプが各問で得られる最大点の25問合計）で
   割り、×100して正規化点を出す。
3. 正規化点の合計に対する比率を「表示比率」として結果画面に使う。
4. 第1位と第2位の正規化点差が5点未満なら混合傾向として明示する。
5. 上位3つがすべて5点未満の差なら、順位を弱く表示し「状況適応傾向」を併記する。
6. 完全同点の場合は次の順で決める。すべて一致すれば同順位のまま表示する。
   1. 境界質問の関連点（同点の2タイプ双方が選択肢として登場する問だけで、
      それぞれが実際に得た点の合計）
   2. 主要3点（+3の主要タイプ加点）を獲得した回数
   3. 危機・成功後質問（第18・24・25問）で得た点
   4. 同順位として表示

`scripts/score_diagnostic.py` は上記1〜6を実装済み。標準版25回答をまとめて
採点するときは、会話中に暗算・推定せず、必ずこのスクリプトへ通す。

## 現在課題の判定

- 課題はタイプ選択肢から推定しない。補助質問1〜5（`questions.md`「課題確認用の補助質問」）
  と、上位課題への追加の事実確認質問（`scoring.md`「根拠不足への対応」）から採点する。
- 「確認できた」と表示するには、異なる質問IDから独立根拠が2件以上必要。1件は
  必ず「参考」と明示する。同じ設問から複数の事情を読み取っても根拠は1件として数える。

## 事業段階・属性

- 事業段階、従業員規模、共有したい相手（`questions.md`「事前属性」）はタイプ点・課題点に
  加えない。事前確認としてそのまま保持する。

## 結果を示すときの表現

- 結果は断定せず「今回の回答では傾向が出た」と表現する。
- 10タイプの％は傾向構成の表示であり、統計的確率や能力値ではないと明記する。
- 特定商品・サービスへ結論を誘導しない。適合する提案がなければ提案なしとする。
- 公開名は日本語だけを使う。英語名・英語併記・英語略称を出さない。`naming.md` で
  未確定の内部識別子（T01〜T10）をそのまま公開名として出さない。
